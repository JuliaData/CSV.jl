# CSV.jl 1.0 — expected-use-case & competitor gap analysis

Date: 2026-09-02. Branch `kernel-proveout` @ `eefe404` (read-only). Env: Julia 1.12.6, 8 threads, Tables.jl `jq/scan` @ `0a8ae5e` (v1.14.0, local dev), DataFrames, Arrow, InlineStrings, PooledArrays, CategoricalArrays.

**Method.** The 1.0 surface was taken from `src/CSV.jl`, `src/api.jl`, `src/write.jl`, `src/scan.jl`, `docs/kernel-README.md`, `docs/review/{csv-issues-audit,streamed-source-plan,RESPONSES}.md`. Every "verified" cell below was executed today: five probe scripts (`$SP/gap/p1_types.jl` … `p5_scan.jl`, outputs `p1.out` … `p5.out`, ~330 probes). "from reading" = read in the source, not executed. Competitor spellings cite primary docs fetched today (list at the end); the few I could not fetch (polars Python API pages render JS-only — I used the r-polars mirror and the docs.rs `SerializeOptions` page; CsvHelper's API pages 404) are marked *(unverified)*.

**Scope boundaries.** The audit's Tier A/B/C and won't-fix triage is not repeated; where I disagree with a won't-fix I say so explicitly. Settled 1.0 decisions are not re-argued, but each is assessed for *migrant confusion* against how competitors spell the same thing.

## Executive summary — top 10 gaps by adoption impact

| # | Gap (severity) | Who hits it | One-line proposal |
|---|---|---|---|
| 1 | **`CompactString` cannot be built from a `String`, and the `CSV.read(path, DataFrame)` string column is immutable** — `push!(df, row)`, `df.col[i] = "x"`, `append!(df, other)` all throw; `match(r"…", s)` / `split(s, r"…")` throw (BLOCKER for DataFrames-first users; verified) | everyone coming from 0.10, pandas, polars who edits a frame after reading | Add `CompactString(::AbstractString)` + `convert` (owned copy), make `CompactStringVector` support `setindex!`/`push!`/`resize!` (or hand DataFrame a mutable `Vector{CompactString}` through `CopiedColumns`), forward `Base.match`/`findnext(::Regex)`/`reverse` the way InlineStrings does |
| 2 | **`TRUE`/`FALSE`, `True`/`False`, `T`/`F` are no longer Bool** (0.10 default `TRUE_STRINGS = ["true","True","TRUE","T","1"]`; verified 1.0 → String) | every R (`write.csv` → `TRUE/FALSE`), Excel (`TRUE/FALSE`) and pandas (`True/False`) export | Keep "strict" but case-insensitive: default `truestrings=["true","True","TRUE"]`, `falsestrings` analog (no 1/0, yes/no); accept `Dict(col => [...])` per column; put the change on the migration guide's first screen |
| 3 | **`scan=Tables.Scan(...)` throws `MethodError: bind`** against the current Tables `jq/scan` (renamed to `Tables.resolve`) — the headline pushdown feature does not run (verified; generic `Tables.scan(File, scan)` works) | anyone trying the 1.0 pushdown story | Rename in `src/scan.jl:94`, pin `Tables = "1.14"` for the Scan path, add a CI lane against the branch |
| 4 | **Bad-line policy has no `:skip`/`:warn`, `CSV.read(src, DataFrame)` swallows problems silently, and `Problem` lacks the raw line, column *name*, source file and physical line** (MAJOR; verified) | pandas `on_bad_lines`, DuckDB `store_rejects`, readr `problems()` users | `on_error ∈ (:collect, :warn, :skip, :error)`; `Problem(row, line, col, name, pos, kind, message, raw, source)`; `Tables.istable(Vector{Problem})`; `CSV.read` prints a one-line readr-style summary when problems exist |
| 5 | **Timestamps**: `2024-01-01 00:00:00` (space) is not auto-detected; sub-millisecond fractions are **silently truncated** (`.123456789` → `.123`, no Problem) (MAJOR; verified) | DB dumps, pandas/polars/Spark exports (µs/ns everywhere) | Add space-separated ISO to the auto lattice; record a `:precision_loss` Problem (or promote to String) when fractional digits > 3; document `types=Dict(:t => NanoDate)` via the `tryparse` door |
| 6 | **Encodings & compression**: no `encoding=`; Latin-1 bytes silently become invalid-UTF-8 strings; a UTF-16 BOM file dies with `Symbol name may not contain \0`; zstd/bz2/xz/zip inputs yield garbage or that same error (MAJOR; verified) | Excel "Unicode Text" (UTF-16LE TSV), legacy Latin-1 exports, data-lake `.zst` | `encoding=:latin1 | :utf16 | :utf16le | …` (latin1/utf16 built in, StringEncodings ext for the rest); magic-byte detection of UTF-16/zstd/bz2/xz/zip with an actionable error; `CSV.register_decoder!(magic, f)` extension hook (CodecZstd/CodecBzip2/CodecXz/ZipArchives); `compress=:zstd` on write |
| 7 | **No per-column `missingstring`** (pandas `na_values` dict, polars `null_values` dict, pyarrow per-column via `column_types`+`null_values`) and no documented broad-NA recipe (`NA`, `NULL`, `N/A`, `null`, `-` all come back as String; verified) | migrants who never typed `na_values` because pandas' default list covered it | `missingstring=Dict(:col => [...])`; export `CSV.NA_STRINGS` (pandas' default list) so `missingstring=CSV.NA_STRINGS` is the one-liner; keep empties-always-missing |
| 8 | **`Rows`/`Chunks` lost `select`/`drop`** (0.10 had them), `Chunks` yields the internal `CSVKernel.ParsedTable`, `ntasks` still means "batch count", no row-count chunking, and gzip/IO sources are read whole into RAM (streaming designed, not built) (MAJOR; verified) | larger-than-RAM users, pandas `chunksize`, polars `read_csv_batched` | Restore `select`/`drop` on Rows/Chunks (projection is free on the index); yield `CSV.File`; `Chunks(nchunks=, chunkbytes=, chunkrows=)`; ship `StreamedSource` before 1.0 or document the RAM bound loudly |
| 9 | **Selection ergonomics**: `select=r"^x"` and `select=[:a => :new]` raise bare `MethodError`s (Scan does both), no `drop=[:end]`/negative index, no `offset=`, no `skipto="pattern"`, no `rownumber=`, no glob/directory input, `source=true` refused (nice-to-have → MAJOR in aggregate; verified) | fread/polars/DuckDB users | Accept Regex and `Pair` items in `select` (or route to Scan with a clear error), `drop=[:end]`/`select=Not(...)`, `offset=`, `skipto=r"…"`, `rownumber=:idx`, `File(glob"*.csv")`/`readdir`, `source=true ⇒ :source` |
| 10 | **Writer**: no `quotestyle=:nonnumeric`, no `datetimeformat`/`timeformat`, no `float_precision`, no `select=`, no zstd; retired 0.10 kwargs (`transform`, `quotestrings`, `bufsize`, `compress=true`, `header=false`) surface as raw `MethodError`/`TypeError` instead of a hint (verified) | Excel-bound exports, 0.10 scripts | Add `:nonnumeric`; `dateformat`/`datetimeformat`/`timeformat`; `float_precision=n` shorthand; a writer `_LEGACYKW` map |

Honourable mentions (nice-to-have): `header=:auto` (fread `header="auto"`, DuckDB, `csv.Sniffer.has_header` — the internal sniffer already detects it, `File` ignores it), `CSV.read(src, Matrix)` (audit A2 residual), exhausted-IO silent empty File (audit A6 not done), `show(::File)` prints `CSVApi.File("<GenericIOBuffer>")` with no data preview, `sniff` stays private, single-row single-column time files elect `':'` as delimiter.

## 1. Bad-line handling

| Competitor | Spelling (cited) | CSV.jl 1.0 | Gap / proposal |
|---|---|---|---|
| pandas | `on_bad_lines={'error','warn','skip'}` or callable `(bad_line: list[str]) -> list[str] \| None` — "a line with too many fields" only [pandas read_csv] | `on_error=:collect \| :error` only — `:skip`, `:warn` rejected (**verified**). Long rows are truncated + `:long_row` Problem; short rows padded + `:short_row` Problem; `strict=true ⇒ :error` (**verified**) | Add `:skip` (drop the row — the index knows every row boundary, so this is a mask) and `:warn` (collect + one `@warn` summary line). A callable is not needed: `problems(f)` + `Tables.Scan` cover it |
| polars | `ignore_errors` "Keep reading the file even if some lines yield errors"; `truncate_ragged_lines` "Truncate lines that are longer than the schema"; `raise_if_empty` [r-polars mirror; docs.pola.rs read_csv] | ragged long rows always truncated (with a Problem); empty file → 0×0 `File`, no error (**verified**) | `truncate_ragged_lines`-style *silence* for trailing empty fields is audit Tier C (#793); fine. Consider `raise_if_empty`-like `ArgumentError` for a zero-byte source (pandas `EmptyDataError`, polars `NoDataError`) |
| DuckDB | `ignore_errors`, `store_rejects`, `rejects_scan`/`rejects_table`/`rejects_limit`, `null_padding`; `reject_errors` columns: `scan_id, file_id, line, line_byte_position, byte_position, column_idx, column_name, error_type, csv_line, error_message`; error types CAST / MISSING COLUMNS / TOO MANY COLUMNS / UNQUOTED VALUE / LINE SIZE OVER MAXIMUM / INVALID ENCODING [DuckDB faulty CSV] | `Problem(row, col, pos, kind, message)` (**verified** fieldnames); kinds `:short_row :long_row :invalid_value :invalid_quoted_field :unclosed_quote`; `maxproblems` caps retention (show says "100 problem(s) recorded — 3 retained") (**verified**). Multi-file: rows are offset but **no file id** (**verified**) | Rejects-as-a-table is the modern bar and CSV.jl is 80% there. Add: `line` (physical line — the tape knows it), `name::Symbol`, `source` (path or index), `raw` (a `CompactString` view of the offending row — zero-copy, so cheap), and `Tables.istable(::Type{Vector{Problem}}) = true` (today `DataFrame(problems(f))` and `CSV.write(io, problems(f))` already work through Tables' struct-vector fallback, but `Tables.istable` is `false`, **verified**) |
| readr | `problems(x)` → tibble `row, col, expected, actual, file`; warning "N parsing failures" + printed summary; `stop_for_problems()` [readr problems] | `CSV.problems(f)` (no `expected`/`actual` split, message carries both); **`CSV.read(src, DataFrame)` has no problems channel at all — silent** (**verified**); no printed summary | `CSV.read` should emit one summary line (`┌ Warning: 3 parse problems (2 short_row, 1 invalid_value); pass on_error=:collect to silence, CSV.problems(...)`) unless `on_error=:collect`; or attach problems as DataFrames table-level metadata (`DataAPI.metadata!(df, "csv.problems", …)`) when the sink supports it. `on_error=:error` should throw a typed `CSV.ParseProblems <: Exception` carrying the vector, not `ErrorException("CSVKernel: …")` (**verified** current message) |
| pyarrow | `ParseOptions.invalid_row_handler(InvalidRow(expected_columns, actual_columns, number, text)) -> 'skip' \| 'error'` [pyarrow ParseOptions] | no callback; equivalent info minus `text` | covered by `:skip` + `raw` above |
| Spark | `mode=PERMISSIVE\|DROPMALFORMED\|FAILFAST`, `columnNameOfCorruptRecord` [Spark CSV] | `:collect` ≈ PERMISSIVE, `:error` ≈ FAILFAST, DROPMALFORMED missing | `:skip` = DROPMALFORMED |
| Go / Rust / CsvHelper | Go `FieldsPerRecord` (0 = lock to first row, <0 = ragged ok), `LazyQuotes`, `ParseError{StartLine, Line, Column}` [Go csv]; Rust `flexible(true)`, `ErrorKind::UnequalLengths{pos, expected_len, len}`, `Position{byte,line,record}` [docs.rs csv]; CsvHelper `BadDataFound`, `MissingFieldFound`, `ReadingExceptionOccurred` callbacks *(unverified)* | always "flexible" with Problems; byte offset yes, physical line no | add `line` to `Problem` (see above) |
| **Malformed quotes** | Go `LazyQuotes`; pandas/Rust treat a quote not at field start as literal; DuckDB sniffs `quote` ∈ {`"`, `'`, none} [DuckDB auto-detection] | pinned: every `"` toggles. `1,x"y\n2,y` → **1 row**, cell `x"y\n2,y\n`, two Problems; `quoted=false` recovers 2 rows (**verified**) | Not re-arguing the kernel rule, but for adoption the *sniffer* should score `quoted=false` (field-count consistency) as DuckDB does, and the Problem message should name the fix (`pass quoted=false`) — the audit's B9 docs-only answer under-weights how common stray quotes are in scraped data |

## 8. Migration from 0.10 — guide skeleton

0.10 facts verified in `legacy/src/`: `DEFAULT_STRINGTYPE = InlineString`, `DEFAULT_POOL = (0.2, 500)`, `DEFAULT_ROWS_TO_CHECK = 30`, `DEFAULT_MAX_WARNINGS = 100`, `TRUE_STRINGS = ["true","True","TRUE","T","1"]`, `FALSE_STRINGS = ["false","False","FALSE","F","0"]`; `Rows(select, drop, pool=false, stringtype=PosLenString, lazystrings, reusebuffer)`; `write(compress::Bool, header::Vector, writeheader, bufsize, quotestrings, transform, bom, delim::Union{Char,String})`.

1. **First screen — three behaviour changes that silently alter data**
   - Empty unquoted cell ⇒ `missing`, always. `missingstring=""`/`nothing` no longer yields `""` (audit B1 still open — decide, then document either way).
   - Bool: only `true`/`false` infer (see gap #2). `TRUE`/`T`/`1` columns are now `String`; pass `truestrings=`/`falsestrings=` or (my recommendation) change the default.
   - `pool=false`: string columns are no longer `PooledArray` by default → `levels(df.col)` and `refarray` code breaks; `pool=(0.2, 500)` restores 0.10.
2. **String type**: `String7`/`String15`… → `CompactString` (`stringtype=InlineString` with InlineStrings loaded restores the old types — **verified**). Downstream code that dispatches on `InlineString` or calls `String7("x")` changes; `String(x)` copies out. Regex `match`/`split` need `String(x)` today (gap #1). Zero-copy caveat: the column retains the input buffer (mmap on Windows: `GC.gc()`/`buffer_in_memory=true` before `rm`).
3. **Retired keywords (hard errors with hints, verified)**: `silencewarnings`, `debug`, `parsingdebug`, `lazystrings`, `tasks`, `threaded`, `rows_to_check`/`lines_to_check` → `nsample`, `ignoreemptylines` → `ignoreemptyrows`, `datarow` → `skipto`, `type` → `types`, `missingstrings` → `missingstring`, `dateformats` → `dateformat`. Kept as aliases: `strict` (⇒ `on_error=:error`), `maxwarnings` (⇒ `maxproblems`), `reusebuffer` (inert), `buffer_in_memory`.
4. **Function-typed `types`/`select`/`drop`** retired ("retired; pass a list (or use Tables.Scan for expressions)", verified) → `types=Dict(r"^x_" => Float64)` (Regex keys work, verified) or `scan=Tables.Scan(select=[r"^x_"])`.
5. **Warnings → data**: `@warn` spam is gone; `CSV.problems(f)`; `CSV.read(src, DataFrame)` is silent (gap #4).
6. **`CSV.Rows`**: `select`/`drop`/`pool` gone (gap #8); default cell type `CompactString` (was `PosLenString`); `PosLenString`/`Row2` no longer exist (verified `isdefined` false).
7. **`CSV.Chunks`**: eltype `CSVKernel.ParsedTable` not `CSV.File`; schema stable across chunks (0.10 could change per chunk); `ntasks` semantics unchanged (rename pending); batches byte-even not row-even.
8. **Multi-file `File(::Vector)`**: string columns come back `String` regardless of `stringtype` (verified); `source=` works for one-element vectors (new); collision with a data column is an error.
9. **Writer**: `compress=true` → `compress=:gzip` (or `.gz` path); `header=false` → `writeheader=false`; `quotestrings=true` → `quotestyle=:all`; `transform=` gone (pre-transform the table); `bufsize` gone; `delim` single byte only; empty string now written `""` (quoted) so it round-trips distinct from `missing` (verified) — 0.10 wrote both as nothing.
10. **Numbers**: `Int64` overflow now widens to `Int128` (0.10: `Float64`) — code doing `Int(x)` on id columns is safe, code assuming `Float64` breaks; `nsample` rarely matters (column-local promotion).
11. **Sources**: URLs now work; gzip/IO sources are read whole into RAM (0.10 spooled to a tempfile) — see gap #8.
12. **Types**: `Union{String,Missing}` declared columns stay `Union{…, Missing}` even with no missings (0.10 parity, verified); narrow ints out of range → `missing` + Problem (verified).

## Where CSV.jl 1.0 is ahead of the field (specific, verified where marked)

- **Deterministic parallel chunking** (parity-composed quote state): identical bytes-in → identical table at any `ntasks`/`chunkbytes`; no speculate-and-retry (DuckDB) and no "set `num_threads=1` if you have embedded newlines" (readr/vroom docs literally say this). Verified structurally by the test matrix per README; not re-run today.
- **Sample-independent type inference** — column-local promotion re-parses only the conflicting column; 3 000 ints + `"x"` → String, 50 000 ints + `2.5` → Float64 with default `nsample` (**verified**). polars `infer_schema_length`, pyarrow streaming ("types frozen after first block"), pandas `low_memory` mixed-type warnings, Spark `samplingRatio` all have a sample-size failure mode.
- **Problems as data with byte offsets**, bounded by `maxproblems`, escalation post-parse (**verified**) — only DuckDB's `store_rejects` is comparable; readr's tibble has no byte position.
- **Exact `limit`/`skipto`/`footerskip` as index arithmetic under threads** (audit #959: 3 M-row file `skipto=2.9M, limit=1000` in 0.1 s).
- **Int128 lattice** (`18446744073709551615` → Int128, **verified**) — pandas → object/float, polars → error or Float64, DuckDB → HUGEINT only if declared, fread → integer64/character.
- **`CompactString` zero-copy columns** — 16-byte Arrow-`Utf8View` payloads, no per-cell allocation, `String`-compatible hashing/equality (**verified**); vroom ALTREP is the only analogue, and it is R-only.
- **`CSV.lazy` / `LazyFile`** — index-only first look with O(1) typed cell access and `File(lf)` reusing the index (**verified**); no competitor exposes the structural index as a table.
- **`Tables.Scan` pushdown incl. two-phase masked filter** (predicate columns parse first, the rest only where the mask holds) — polars `scan_csv` is the peer; pandas/readr/fread have nothing. (Blocked today by gap #3.)
- **Stable-schema `Chunks`** (whole-index type prepass, **verified**) — pyarrow's `open_csv` freezes on block 1, polars `read_csv_batched` can differ per batch.
- **Multi-file union by name with promotion and `source=` labels** (**verified**) ≈ DuckDB `union_by_name` + `filename`; pandas needs `pd.concat`, readr `id=`.
- **Custom scalar types through `Base.tryparse`** inside the monomorphic column loop, in `File` *and* `Rows` (**verified**) — pandas `converters` run per cell in Python.
- **Writer**: byte-deterministic across threads, 3–56× faster than 0.10, ahead of polars on string/mixed shapes at 200 k rows (RESPONSES #26); quoted-empty vs missing round-trips (`""` vs empty, **verified**) — pandas/polars conflate them.
- **Cold start**: PrecompileTools workload → first `CSV.File` ~1 ms (RESPONSES/audit #974); pandas import + first read is slower.
- **Regex-keyed Dicts** for `types`/`dateformat`/`pool` (**verified**), `header=[1,2]` merged headers, `transpose=true`, `Cmd` sources, `comment=`, `footerskip=` — each exists in at most one or two competitors.
- **Clear retired-keyword errors** on the reader (**verified** for 12 legacy kwargs) — polars/pandas deprecations are warnings that later break silently.
